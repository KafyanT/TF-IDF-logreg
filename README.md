# Отчёт: TF-IDF + Logistic Regression

Код: [`tfidf_logreg_colab.py`](tfidf_logreg_colab.py), реализация TF-IDF с нуля: [`tfidf_from_scratch.py`](tfidf_from_scratch.py).

## Задача

Ранжирование объявлений внутри поискового запроса (`query_id`) по вероятности контакта с продавцом (`item_contact`). Метрика — NDCG@10, усреднённая по запросам с хотя бы одним положительным примером.

## Метод

**TF-IDF + Logistic Regression** — текстовый baseline без числовых признаков.

**Признак:** `query_text + " " + item_title` — объединение поискового запроса и заголовка объявления.

**Векторизация:** TF-IDF по тем же формулам, что в `tfidf_from_scratch.py` (знаменатель TF незначительно отличается — см. примечание ниже):

$$TF(t,d) = \frac{\text{count}(t,d)}{|d|}$$

$$IDF(t) = \ln\!\left(\frac{N+1}{DF(t)+1}\right)+1 \quad \text{(сглаженный)}$$

$$\text{TF-IDF}(t,d) = TF(t,d) \cdot IDF(t)$$

Словарь ограничен 50 000 наиболее частыми токенами. Реализация с нуля (`tfidf_from_scratch.py`) используется для демонстрации на примерах; на полном датасете применяется `sklearn`: `CountVectorizer` → L1-нормировка строк → `TfidfTransformer(smooth_idf=True, norm=None)`. Знаменатель TF в sklearn — сумма счётчиков только словарных токенов (OOV исключены); в `tfidf_from_scratch` — полная длина документа. Различие незначительно при большом словаре.

**Классификатор:** Logistic Regression (`saga`, `C=1.0`, `max_iter=500`), обучается на разреженной TF-IDF матрице, предсказывает вероятность контакта.

**Ранжирование:** объявления внутри запроса сортируются по убыванию `predict_proba[:, 1]`.

## Валидация

5-фолдовый CV по `query_id`: запросы **с хотя бы одним позитивом** случайно распределяются по фолдам (`np.random.default_rng(42).integers(0, 5, n_pos_queries)`), все строки запроса попадают в один фолд — утечки таргета нет. Запросы без позитивов попадают в каждый train-фолд, но никогда в validation.

## Сравнение с другими моделями

Все модели ниже оценены на OOF по одним и тем же фолдам (5 фолдов, `n_pos_queries`):

| Модель | OOF NDCG@10 |
|--------|------------|
| **TF-IDF + LogReg (этот эксперимент)** | **0.4524** |
| LightGBM lambdarank, табличные признаки | см. основной README |
| LightGBM lambdarank, все признаки (итоговая модель) | 0.5244 |

**Справочно (несопоставимый скоуп):** сортировка по `click_conv` без обучения даёт NDCG@10 ≈ 0.4535 на фолде 0 основного ноутбука.

## Выводы

- TF-IDF + LogReg даёт NDCG@10 = **0.4524**, что незначительно ниже простейшего baseline — сортировки по `click_conv` (0.4535). Это означает, что **текст заголовка и запроса в отрыве от числовых признаков почти не добавляет сигнала**.
- Отставание от итоговой LightGBM-модели (~0.07 по NDCG) объясняется тем, что LogReg не видит числовых признаков (`price`, `click_conv`, категории) и не умеет моделировать нелинейные взаимодействия.
- Результат согласуется с наблюдением из основного ноутбука: TF-IDF косинус сам по себе — слабый ранкер, но в составе LightGBM как один из признаков он вносит вклад.

**Возможные улучшения:**
- Добавить числовые признаки через `scipy.sparse.hstack`.
- Использовать BM25 вместо TF-IDF (лучше учитывает длину документа).
- Добавить `item_description` частично (первые N символов).
